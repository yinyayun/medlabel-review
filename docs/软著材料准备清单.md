### 2. 核心材料

- [ ] 按办理系统要求填写的软件著作权登记申请表。

《计算机软件著作权登记办法》第十条规定，一般交存的程序和文档鉴别材料由源程序和一种文档各自的前、后连续 30 页组成；各自不足 60 页的提交全部。除特定情况外，源程序每页不少于 50 行、文档每页不少于 30 行。实际排版与提交形式应核对办理时的指南。**这不是最低开发行数要求，不应填充无用代码或重复文档凑页数。**

依据：[国家版权局《计算机软件著作权登记办法》](https://www.ncac.gov.cn/xxfb/flfg/bmgz/202410/t20241015_869486.html)。

### 3. 从本仓库整理哪些内容

| 材料 | 建议来源 | 提交前检查 |
| --- | --- | --- |
| 项目源代码 | `app/` 下后端、解析、比对、报告和前端代码 | 固定版本；记录文件排列顺序；确保为实际代码 |
| 操作说明 | `docs/用户操作手册.md` | 按最终界面补充真实截图，核对按钮与步骤 |
| 技术说明 | `docs/软件设计说明书.md` | 与最终模块、数据结构及边界一致 |
| 功能说明 | README、操作手册和运行演示 | 只填写已经实现、能验证的功能 |
| 运行环境 | README、依赖文件 | 核对实际 Python 版本和依赖 |
| 权属材料 | 申请人及有关单位提供 | 身份、合同、署名等内容一致 |

Python 环境、依赖库、缓存、日志、真实业务附件、数据库、密钥或账号信息不应混进源程序材料。对于第三方库和外部素材，应保留必要的来源、许可证和使用范围记录，不能把第三方全部代码声明为自己的开发成果。

### 5. 提交前的一致性检查

- [ ] 软件名称、版本、权利人署名在所有材料中一致。

- [ ] 已检查第三方依赖和素材的使用条件。
- [ ] 已确认申请人身份、开发方式及权利归属。
- [ ] 已按办理时的要求检查格式、签章、附件及补正事项。
