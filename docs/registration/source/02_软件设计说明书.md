### 1. 软件概述与设计目标

本软件围绕药品说明书资料的版本管理与人工审核，建立“药品档案—说明书版本—章节差异—审核意见—导出报告”的关联关系。使用者将同一药品的新旧说明书归入同一档案，检查提取文本与章节结构，创建比对后逐项确认或忽略差异，保留操作过程。

系统的主要设计目标为：保留可回查的原始资料；按说明书章节定位变化；突出数字、单位及重点章节变化；将文本比对与人工审核衔接；提供便于查阅、整理及程序处理的报告。软件采用确定性规则和文本差异算法，不通过生成式模型推测原文含义。

V1.0 面向单机、单个可信操作者使用。药学审核结论由使用者负责，程序输出的是文本变化和记录状态，不构成药品安全性、有效性或监管审批结论。本版本未实现 OCR、账户认证、多人权限隔离、电子签名或医院信息系统对接。

### 2. 运行环境与技术组成

程序使用 Python 3.11 及以上版本运行，浏览器访问本机 HTTP 服务。已验证环境包含 Python 3.11、Python 3.12 和 Chromium。代码提供 Windows PowerShell 与 macOS/Linux Shell 启动脚本，具体安装使用说明见配套用户操作说明书。

| 组成 | 实现方式 | 作用 |
| --- | --- | --- |
| 服务端 | Python、FastAPI、Uvicorn | HTTP 接口、业务验证、静态资源服务 |
| 数据保存 | SQLite、Python sqlite3 | 档案、版本、比对、审核及操作记录 |
| 文档解析 | pypdf、python-docx、标准编码解码 | PDF、DOCX、TXT 文字提取 |
| 差异算法 | Python difflib.SequenceMatcher | 章节内字符级差异片段 |
| 用户界面 | HTML、CSS、原生 JavaScript | 浏览器交互、差异展示、表单与筛选 |
| 报告 | HTML、CSV、JSON | 阅读打印、表格整理、结构化交换 |

前端由同一服务端提供，不要求 Node.js 构建工具。依赖安装完成后，本地文档处理不需要外部网络、大模型密钥或第三方数据库服务。运行依赖见 requirements.txt，验证环境完整版本见 requirements-lock.txt。

### 3. 总体结构与模块划分

系统采用浏览器界面、HTTP 业务接口、文档处理与比对模块、本地存储四部分结构。浏览器通过 fetch 请求业务接口；接口先校验输入，再调用解析、比对或报告模块；数据库保存结构化记录，上传文件保存在独立目录。处理结果以 JSON 返回界面或以附件形式下载。

| 模块 | 对应文件 | 主要职责 |
| --- | --- | --- |
| 启动模块 | run.py | 解析监听地址、端口、数据目录并启动服务 |
| 应用接口模块 | app/main.py | 应用初始化、输入模型、业务路由、请求校验 |
| 数据模块 | app/database.py | 建表、连接、事务及日志写入 |
| 文档模块 | app/documents.py | 文件提取、标题规范化、章节划分、人工校正校验 |
| 比对模块 | app/comparison.py | 章节匹配、变化分类、差异片段、关注标记 |
| 报告模块 | app/reports.py | 来源信息、审核状态及差异的多格式输出 |
| 示例模块 | app/demo.py | 明确标注的模拟药品和说明书文本 |
| 界面模块 | app/static/ | 工作台、药品版本、比对审核、操作记录 |

同一说明书版本可参与多个比对，每个比对记录固定一组旧版、新版及生成时的差异。审核记录附属于具体差异；再次建立比对不会在后台重算或覆盖原有任务。

### 4. 数据库与附件设计

数据库文件名为 medlabel.sqlite3，原始附件保存在同一数据目录下的 uploads 子目录。数据库包含六张表。业务对象的 id 使用 INTEGER PRIMARY KEY；日期时间以 TEXT 保存，版本日期采用 YYYY-MM-DD，操作时间采用带时区的 UTC ISO 格式。JSON 内容存于 TEXT 字段，由应用进行序列化和解析。

#### 4.1 药品档案表 drugs

| 字段 | 类型 | 含义与约束 |
| --- | --- | --- |
| id | INTEGER | 主键 |
| name | TEXT | 药品名称，非空 |
| manufacturer | TEXT | 厂家，非空，默认空串 |
| specification | TEXT | 规格，非空，默认空串 |
| approval_number | TEXT | 批准文号，非空，默认空串 |
| notes | TEXT | 备注，非空，默认空串 |
| created_at | TEXT | 创建时间，非空 |

药品档案用于归集资料，不向外部监管数据库核验药品名称或批准文号。

#### 4.2 说明书版本表 versions

| 字段 | 类型 | 含义与约束 |
| --- | --- | --- |
| id | INTEGER | 主键 |
| drug_id | INTEGER | 所属药品，外键指向 drugs.id |
| label | TEXT | 版本名称 |
| version_date | TEXT | 版本日期 |
| source | TEXT | 资料来源描述 |
| filename | TEXT | 清理路径后的原始文件名 |
| sha256 | TEXT | 原始文件字节的 SHA-256 |
| storage_name | TEXT | 随机生成的内部附件名 |
| text | TEXT | 提取原文 |
| sections | TEXT | 章节列表 JSON |
| warnings | TEXT | 提取或人工校正提示 JSON，默认空列表 |
| created_at | TEXT | 导入时间 |

版本表以上业务字段均设置 NOT NULL。每个章节包括 key、title、text、start_line、end_line。行号指向提取文本，不能直接换算为 PDF 页面坐标。接口对外不返回 storage_name。

#### 4.3 比对表 comparisons

| 字段 | 类型 | 含义与约束 |
| --- | --- | --- |
| id | INTEGER | 主键 |
| drug_id | INTEGER | 药品外键 |
| old_version_id | INTEGER | 旧版本外键，指向 versions.id |
| new_version_id | INTEGER | 新版本外键，指向 versions.id |
| unchanged_sections | INTEGER | 正文未变化的章节数 |
| warnings | TEXT | 章节重排、重复标题等提示 JSON |
| created_at | TEXT | 比对创建时间 |

旧、新版本编号须不同。应用层同时校验所属药品相同、旧版日期不晚于新版。任务总差异数、待复核数和完成状态由其差异记录汇总计算，未单独保存易失配的统计字段。

#### 4.4 差异与审核表 changes

| 字段 | 类型 | 含义与约束 |
| --- | --- | --- |
| id | INTEGER | 主键 |
| comparison_id | INTEGER | 所属比对，外键指向 comparisons.id |
| payload | TEXT | 章节差异内容 JSON |
| status | TEXT | pending、confirmed 或 ignored，默认 pending |
| note | TEXT | 审核意见，默认空串 |
| reviewer | TEXT | 本地审核员显示名称，默认空串 |
| reviewed_at | TEXT | 最近一次审核时间，未审核时可为空 |

payload 保存章节键、章节名称、变化类别、关注级别、旧文、新文、两侧位置、差异片段和标记。status 使用数据库 CHECK 约束限制取值。审核信息单独保存，使原始比对结果与后续处理意见相互区分。

| 表 | 字段 | 类型 | 含义 |

| audit | detail | TEXT | 操作详情，通常为 JSON |
| audit | actor | TEXT | 本地操作者显示名称 |
| audit | created_at | TEXT | 记录时间 |

audit 的 entity_type 和 entity_id 构成应用层关联，不是指向 changes 或其他业务表的数据库外键。settings 的 demo 键保存演示药品与比对编号，避免重复加载生成重复示例。系统为版本所属药品、差异所属比对、比对版本组合建立索引。

### 5. 文件导入与原始资料保存

导入流程依次执行档案存在性检查、元信息验证、文件读取、格式解析、正文长度校验、章节识别、附件保存、数据库写入及操作记录写入。文本粘贴入口将文本编码为 UTF-8，以 pasted-text.txt 形式进入相同处理链。

文件名先清理路径分隔符并取末级文件名；内部文件名采用 UUID 加扩展名，防止上传名称覆盖其他附件。SHA-256 根据原始上传字节计算。提取文本与人工整理章节分开保存：校正章节不改变文件内容、摘要和原始提取文本。摘要只用于核对内容，不证明文件发布者身份或官方核准状态。

数据库写入失败时回滚事务，并清理该操作新建的附件。文件系统与数据库并非同一种事务资源，正常异常路径可清理新文件，突然断电等情况仍需通过备份和人工核对恢复。V1.0 未提供版本原件覆盖或删除接口。

#### 5.1 各格式提取策略

TXT 依次尝试 utf-8-sig、GB18030 解码，统一换行、去除 BOM，拒绝空文本和空字符。PDF 检查文件标识、加密状态、页数及图片资源后提取文字。为避免“扫描正文加可提取页码”被误认为完整文字，任何检测到的图片均拒绝，包括嵌套 Form、内联图像、图案及批注外观资源中的图片。纯文字 PDF 的各页文字按顺序连接。

DOCX 先检查 ZIP 包规模、压缩比、加密标记及主文档结构。程序按页眉、正文、页脚顺序读取段落，保留表格和文本框内的文字，并避免重复读取嵌套段落。带未接受修订或脚注、尾注的文档拒绝导入。程序不识别 DOCX 图片中的文字，也不保证复原复杂版式，使用者应在导入后核对原件。

#### 5.2 主要输入限制

| 检查位置 | 限制 |
| --- | --- |
| 文件入口 | 原始文件不超过 10 MiB |
| 应用正文 | 提取或粘贴正文不超过 300,000 字符 |
| PDF | 不超过 100 页，拒绝加密和检测到图片的文档 |
| DOCX 包 | 不超过 2,500 个条目；解压体积不超过 40 MiB |
| DOCX 压缩比 | 单条目超过 1 MiB 且压缩比大于 200 时拒绝 |
| 自动章节解析 | 不超过 500 个章节 |
| 人工章节更新接口 | 1 至 200 个章节；标题与正文合计不超过 300,000 字符 |
| 人工章节标题 | 规范化函数实际限制为 1 至 120 字符 |
| 审核意见 | 不超过 3,000 字符 |

文档底层函数另有 1,000,000 字符保护上限，但通过本应用导入时先适用更严格的 300,000 字符限制。人工校正底层函数可接受最多 500 章，而 HTTP 接口限制为 200 章；不能将底层上限当作界面可用上限。

### 6. 章节识别与人工校正

标题识别支持【】和 [] 括号标题；未带括号时，仅将已知标题或已知标题加冒号识别为章节，避免将任意短句误分为标题。标题规范化采用 NFKC、清理序号与空白、明确别名映射。例如“成分”与“成份”使用统一键，“适应证”与“适应症”使用统一键；未使用模糊语义合并。

前言文字作为独立章节保留，无法识别标题的文档保存为“全文”。未知括号标题也保留。重复标题按出现次数形成键，例如“成份”“成份#2”；标题原有井号先转换，防止与次数后缀冲突。每章保存正文及提取文本起止行。

人工校正重新验证标题、正文与数量，清空行号，并记录校正前后的结构。只要某版本已被任一比对引用，系统即拒绝继续修改章节并返回 409；需要更正时导入新版本，保证已有任务保留原审核依据。

### 7. 差异计算与关注标记

程序依据规范化标题和出现次数对齐两版章节。结果按新版章节顺序输出，再补充旧版独有章节：旧版不存在为 added，新版不存在为 removed，两侧均存在但规范化正文不同为 modified。仅章节顺序改变时记录提示，不作为正文变化。

正文比较将连续空白折叠为一个空格并去除首尾空白，再去除中文字符之间的空格。此过程不会把数字间空格直接删除，例如“1 0 mg”不会等同于“10 mg”。原文仍完整保存供展示，规范化仅用于判定是否产生正文变化。

对变化章节使用 SequenceMatcher 生成 equal、delete、insert 片段。替换表现为删除旧片段并插入新片段；删除侧与相同片段可重建旧文，插入侧与相同片段可重建新文。旧、新章节正文长度合计超过 30,000 字符时，采用整段删除加整段插入，并提示人工对照，限制细粒度匹配消耗。

用法用量、禁忌、不良反应、注意事项、特殊人群等配置章节出现变化时标为重点关注。数字或比例序列不同、单位及剂型计量词序列不同，也生成相应标记。数字规则允许中文紧邻数字；该规则只核对字符序列，不进行剂量换算、同义医学判断或风险评分。

重复标题按顺序配对时给出提示，避免用户将自动对应理解为语义认证。自动提取和章节规则不能保证识别全部现实说明书结构，故界面保留原文、来源与人工校正入口。

### 8. 审核状态与事务一致性

变化初始状态为 pending。使用者可确认、忽略或恢复待复核。ignored 必须填写非空原因；confirmed 可附审核说明。每次保存都记录本地审核员名称、时间和意见，并将 revision 加一。恢复待复核也记录为一次操作，不删除此前日志。

客户端提交当前 revision；服务端读取数据库修订号，不一致时返回 409，提示刷新。写入使用 BEGIN IMMEDIATE 事务，完成状态更新和操作记录写入后一起提交，失败则一起回滚。连接开启外键检查与 WAL 模式，锁等待超时为 15 秒。

待复核差异数量为零时，任务状态为 completed；未检出差异的比对也可完成并导出。这表示流程中没有未处理差异，不表示说明书内容得到医学或监管认可。操作者名称来自配置，是记录标签而非经认证身份。

### 9. 界面与交互设计

界面以哈希路由组织工作台、药品与版本、比对与审核、操作记录。药品和比对列表在已加载数据上提供关键字筛选；审核页按状态及关注级别筛选。差异左右并列显示，并使用删除、新增样式区分变化，数字与计量文本可进一步突出。

所有用户文本在 HTML 插入前转义。行内差异渲染前验证片段能准确重建该侧原文，无法重建时回退到原文展示。异步路由使用请求代次避免旧响应覆盖新页面；弹窗打开后同步设置初始焦点，避免延迟聚焦干扰快速填写。表单包含必填项、长度限制、忙碌状态和错误提示。

### 10. HTTP 接口设计

一般请求与响应使用 JSON；文件上传使用 multipart/form-data；文件和报告下载使用附件响应。服务端校验输入模型并拒绝未声明字段。业务异常使用包含 detail 的 JSON 错误信息。

| --- | --- | --- |
| GET | /api/health | 运行状态、版本、模式和审核员标签 |
| GET | /api/dashboard | 档案、版本、比对、待复核统计及最近操作 |
| GET | /api/drugs | 药品列表及版本数量 |
| POST | /api/drugs | 新建药品档案 |
| GET | /api/drugs/{id} | 药品详情 |
| GET | /api/drugs/{id}/versions | 指定药品的版本列表 |
| POST | /api/drugs/{id}/versions | 上传说明书文件 |
| POST | /api/drugs/{id}/versions/text | 保存粘贴文本版本 |
| GET | /api/versions/{id} | 版本、原文及章节详情 |
| GET | /api/versions/{id}/file | 下载原始文件 |
| PUT | /api/versions/{id}/sections | 更新尚未参与比对的章节 |
| GET | /api/comparisons | 比对任务列表 |

### 11. 报告设计

导出时读取当前任务、两份版本和各条审核信息，记录导出时间。HTML 报告包含统计、来源、文件名、SHA-256、旧新正文、定位、差异及审核意见，可独立打开并通过浏览器打印为 PDF。软件不直接调用 PDF 生成服务。

CSV 使用 UTF-8 BOM 编码，包含版本来源、摘要、变化类型、两侧文本、标记及审核信息。对以公式符号开头或可能隐藏公式前缀的内容添加文本前缀，减少表格程序解释为公式的风险。JSON 保留完整结构化内容并追加 exported_at，供程序读取。

HTML 文本进行字符转义；导出文件名只保留安全 ASCII 字符，报告设置限制性内容安全策略。报告反映导出时点状态，后续审核变化不会修改已经下载的文件。

### 12. 配置、访问保护与恢复

run.py 默认监听 127.0.0.1:8000，数据目录默认位于项目目录的 data。直接启动应用时，MEDLABEL_DATA_DIR 指定数据位置；MEDLABEL_REVIEWER 设置审核员显示名称；MEDLABEL_ALLOWED_HOSTS 可追加主机名。

默认主机限制为 localhost、127.0.0.1、::1。写请求要求 X-Requested-With: MedLabelReview；请求含 Origin 时校验协议、主机和端口一致，不开放跨域接口。响应添加防 MIME 嗅探、禁止页面嵌入和不缓存等头部。上述检查用于本地应用访问保护，并不提供用户登录或访问权限分配。

附件下载先校验解析后的路径仍位于 uploads 目录。SQL 值采用参数绑定；允许动态拼接的表名来自内部白名单。日志与原始附件不纳入 Git 仓库。备份应停止服务后完整复制数据库和附件目录；恢复时保持两者对应。当前操作日志可被具备本机管理权限的人修改，不是不可篡改的审计链。
