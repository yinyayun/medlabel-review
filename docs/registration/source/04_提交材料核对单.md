# 药品说明书版本比对与变更审核系统 V1.0

## 提交材料核对单

本核对单用于将本项目整理为可复核的登记材料。技术文档可以先行完成；身份、权属、日期和签章等项目须由申请人按真实情况补充。本文不表示材料已经提交或登记已经获准。

### 1. 材料组成与用途

| 材料 | 本项目准备内容 | 提交前处理 |
| --- | --- | --- |
| 官方软件著作权登记申请表 | 《登记申请信息草稿》提供字段参考 | 在官方办理系统录入并核实全部信息，按要求签章 |
| 源程序鉴别材料 | 由固定代码版本的实际源文件生成 | 核对文件次序、页码、版本、统计范围及前后页截取规则 |
| 文档鉴别材料 | 可选《软件设计说明书》或《用户操作说明书》中的一种 | 本轮设计说明书系统解释背景、需求与实现；操作说明书解释使用步骤与界面，按办理要求选用 |
| 配套技术文档 | 未选作鉴别材料的另一份说明书 | 供补充说明和自查，不将两份都宣称为普遍必交项 |
| 申请人身份证明 | 待申请人准备 | 依实际申请人类型及办理要求提交 |
| 适用的权属或授权材料 | 待申请人判断并准备 | 有合作、委托、任务、许可或权利继受等情况时，提供对应证明 |

《计算机软件著作权登记办法》第九至十一条规定了申请表、鉴别材料和相关证明文件的基本要求。一般交存时，源程序和一种文档分别取前、后各连续 30 页；各自不足 60 页的应提交全部。除特定情况外，程序每页不少于 50 行，文档每页不少于 30 行。排版、图片页及当前电子提交要求应再核对办理时的官方指南。这些规定不是最低开发行数要求，不应添加无用代码或重复文字凑页数。依据：[国家版权局《计算机软件著作权登记办法》](https://www.ncac.gov.cn/xxfb/flfg/bmgz/202410/t20241015_869486.html)。

### 2. 申请人必须补齐的事项

- □ 确认著作权人完整名称与申请人类型。
- □ 确认是否存在学校、用人单位、合作人或委托方的权利关系。
- □ 确认开发方式、权利取得方式及权利范围。
- □ 确认软件作品说明为原创或修改，按情况提供原登记信息及许可证明。
- □ 按实际情况填写开发完成日期。
- □ 核对 GitHub 及其他渠道的实际发布经历，确认发表状态、首次发表日期及地点，不仅凭仓库当前私有状态选择“未发表”。
- □ 按办理要求准备身份证明、适用的权属文件与签章。
- □ 核实实际开发参与和第三方组件权利来源；本项目使用过 AI 辅助开发与文档制作，学校申报或成果认定另核本校要求。
- □ 将“待申请人填写”“待申请人确认”等提示替换为经核实的信息，或按官方表单规则处理不适用项。

不建议在公开代码仓库保存身份证件、完整地址、电话、私人邮箱、签名图像或合同原件。可公开的技术文档与含个人信息的提交材料应分开保存。

### 3. 源程序鉴别材料检查

| 检查项目 | 核对要求 |
| --- | --- |
| 版本基线 | 对应拟登记的 V1.0，注明采用的 Git 提交或归档标识 |
| 实际来源 | 取自项目实际运行源文件，不使用无功能模板替代 |
| 文件排列 | 保存明确的文件次序及各文件起止范围，便于与完整仓库核查 |
| 行数统计 | 说明统计范围和口径；当前结果为“4,505 个物理行；4,079 个非空源代码行；4,490 个显示行；完整显示编排 75 页” |
| 完整页数 | 根据统一排版实际生成，不通过缩放或增加空行凑数 |
| 前后页规则 | 对完整源程序按一般交存规则选择页段；不足 60 页时保留全部 |
| 内容连续性 | 页段内内容连续，不任意删改中间代码以拼接展示 |
| 软件识别 | 页眉或其他识别信息使用准确的软件全称与版本 |
| 可读性 | 文字清楚、未截断；长行换行后仍可对应原文件与源行 |
| 计行说明 | 本次前 59 个提交页各 60 个显示行，末页 50 个；原始行号及续行标记另列，不以显示行数冒充源程序总行数，不把自动校验视为登记机构认可 |
| 排除项 | 不把虚拟环境、第三方库源码、缓存、数据库、日志或真实附件作为本项目源程序混入 |

项目使用开源框架和库。应区分本项目源代码与第三方依赖，核对所使用版本的许可证及必要声明，不将第三方完整代码宣称为自己的开发成果。对外部文件的使用权限也应另行确认。

### 4. 软件文档检查

- □ 软件名称固定为“药品说明书版本比对与变更审核系统”，版本为“V1.0”。
- □ 操作流程覆盖建立档案、导入版本、检查及校正章节、创建比对、人工复核、报告导出和操作记录。
- □ 截图来自实际运行软件，使用明确标注的模拟资料，能够与正文按钮名称和步骤对应。
- □ 操作员显示名称没有被写成经过身份认证的账号或电子签名。
- □ SHA-256 仅用于内容核对，没有被写成官方认证、来源真实性证明或不可篡改证明。
- □ 数字、单位及重点章节提示没有被写成医学风险判断。
- □ 含图片 PDF 的拒绝规则、OCR 不支持等能力边界与软件一致。
- □ 章节校正锁定、忽略原因、并发修订冲突等处理规则描述准确。
- □ 运行环境区分“实际已验证”与“建议配置”，未宣称未经测试的平台已经验收。
- □ 检查 Word 与 PDF 中的表格、截图、页眉页脚和换页，确保无缺字、遮挡、越界或空白异常页。

### 5. 本材料包的使用顺序

1. 先阅读《登记申请信息草稿》，补齐申请人必须确认的字段。
2. 运行归档版本，抽查操作说明书中的界面和主要操作。
3. 从设计说明书或操作说明书中选定文档鉴别材料，并按最终排版页数处理；不把申请填报参考当作官方申请表。
4. 对照源文件清单核查生成的源程序材料，保留完整源程序归档与本次提交页段。
5. 在官方办理系统录入信息，按当前要求提交附件、证明及签章材料。
6. 保留提交版本和受理记录；若收到补正要求，记录变更，并同步更正相关材料。
