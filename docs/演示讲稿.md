# MedLabel Review 演示讲稿

适用场景：毕业答辩、项目介绍或求职面试。预计 5—8 分钟，可根据现场操作调整。所有演示资料使用系统自带模拟示例或自行制作并明确标注的测试文件。

## 1. 介绍问题（约 40 秒）

“这个项目叫药品说明书版本比对与变更审核系统。人工核对两版说明书时，除了找到改了哪些文字，还需要确认章节是否对应、变化来自哪里、谁做了核对，以及处理意见是什么。这个项目把这些步骤连在一起，帮助使用者形成可回查的审核记录。”

## 2. 展示资料归档（约 1 分钟）

打开药品档案和版本列表，展示版本标签、日期、来源和原始文件信息。

“每一份说明书都作为独立版本保存。来源由录入人员填写，文件摘要用于追踪同一份内容，不代表系统验证了说明书的真实性。演示中的药品和文本都是模拟资料。”

## 3. 展示章节整理（约 1 分钟）

展示导入后的章节。若准备演示校正，应使用尚未参与比对的版本；提前参与比对的版本会被锁定。

“系统先将文件转为可处理的文本，再识别章节。遇到复杂排版时允许人工校正。版本进入比对后停止允许修改章节，避免审核完成以后原始依据被悄悄改掉。需要纠错时，应建立新版本。”

## 4. 展示差异与核查（约 2 分钟）

打开一份有修改、新增或删除章节的比对，选择一条有数字或单位变化的示例。

“这里能看到旧版、新版以及对应的文字变化。系统还提供重点章节和数字单位变化提示，帮助安排核查顺序。提示来自文本规则，不表示系统已经做了药学判断。”

核对原文，填写说明并将一条变化标记为已确认。再选择一条适合说明忽略操作的模拟变化，填写明确原因后保存。

“确认和忽略都需要由人决定。忽略必须说明原因；所有修改保留记录。多个页面同时操作时，用修订号防止旧页面覆盖最新结果。”

## 5. 展示报告与记录（约 1 分钟）

导出 HTML 报告，展示版本信息、原文位置、状态和意见；打开操作日志。

“报告保存的是导出时的审核状态。如果还有待复核项，不能把它当作全部审核结束的结论。HTML 适合查阅与打印，CSV 便于表格整理，JSON 便于后续程序处理。”

## 6. 说明技术与验证（约 1 分钟）

“项目采用 FastAPI、SQLite 和浏览器原生前端，可以在本地运行。核心逻辑包括中文章节整理、确定性的文本差异、审核状态保存以及导出转义。测试覆盖情况和执行结果在仓库中提供，演示时以实际运行结果为准。”

如果展示测试，不要将“测试全部通过”扩展为“能正确识别所有说明书变化”。可补充展示自己准备的章节误识别或复杂 PDF 案例，解释系统如何提示并由人校正。

## 可能被问到的问题

| 问题 | 建议回答要点 |
| --- | --- |
| 与普通文字对比有什么区别？ | 有药品与版本归档、章节对齐、重点变更提示、人工审核状态、来源和报告记录 |
| 为什么首版没有使用大模型？ | 核心差异希望可重复、可回查；首版用规则与文本比较，后续扩展也需保留原文依据 |
| 能否用于药品风险判定？ | 当前只能辅助文档核查，不能给出风险、疗效或监管结论 |
| 扫描件是否支持？ | 首版没有 OCR；需先提取并人工核对文字 |
| 是多人审核系统吗？ | 当前是本地单操作员版本，显示名称不代表身份认证 |
| 接下来怎么改进？ | 根据实际使用反馈改进复杂表格、版面定位和文档解析；多人账号与签名需另行设计验证 |
